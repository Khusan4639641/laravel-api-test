# SAFILIFE.KZ Business TZ Audit

Project: `/var/www/project7`  
Branch checked: `safi-frontend-integration`  
Audit scope: Laravel backend, React/Vite frontend, database migrations/seeders, API resources/controllers/services, feature/unit tests.

This document is audit-only. It records current gaps against the new SAFILIFE.KZ business TZ and does not include code fixes.

## Executive Summary

- Package data is the largest mismatch: database schema can support the new TZ, but `PackageSeeder`, upgrade chain, tests, demo users, and public/frontend output still include `BUSINESS` and old package values.
- Referral and binary bonus calculations are data-driven through package percents, which is structurally good, but seeded package percents and multiple tests assert the old business plan.
- PV is cumulative in current services and upgrade adds only additional PV, but activation can still add PV for same-or-higher packages through the generic activation endpoint; this needs stricter business rules.
- Status thresholds match the new TZ, but reward text misses parts of Bronze/Silver rewards and there is no real status bonus payout model/service.
- Bonus X2 is not implemented.
- Deposit is only partially represented as a split of binary bonus into the `bonus` wallet, not a real `deposit` wallet, and deposit purchase 20% cashback is missing.
- Withdrawals support arbitrary payment method strings and admin approval, but the 14-day payout cycle is not enforced. Frontend uses `bank_account`, while settings use `business_account`.
- Frontend mostly loads packages/statuses/products/news from API, but old mock files remain and some dashboard/marketing values are hardcoded or stale.
